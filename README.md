# TikTok 运营助手（dsh-tiktok-ops）

用户提交的是**选题任务**（选题 + 参考素材 + 时长 + 比例），不是提示词。提示词由 agent
按选题写出来，经**脚本审核**后生成视频，再经**审片**后发布，最后回采数据与评论，
用数据反哺下一轮选题。

## 任务流转

**「进行中」是过程状态**，不是可以久留的地方：它只表示「某一步操作正在跑」，并记着
跑的是哪一步（`op.kind`）和失败该退回哪里（`op.from`）。由此得到两条硬规则：

1. **进行中的任务不能改、不能删**（改参数会让正在跑的那一步不知道按哪版算；删了产物就没落点）。
   要改就先「取消当前操作」退回来源状态。
2. **操作失败/取消 → 退回来源状态**，绝不稀里糊涂停在「进行中」。

```
草稿 ──提交──▶ 进行中·生成提示词 ──agent 写提示词──▶ 脚本审核
   ▲                    │                                  │
   └── 失败/取消 ────────┘                        通过 ─────┤───── 驳回
                                                   │        └──▶ 进行中·生成提示词
                                                   ▼              （失败退回脚本审核）
                                          进行中·生成视频
                                                   │
                    失败/取消 ──▶ 脚本审核          │ 成功
                                                   ▼
              脚本审核 ◀── 驳回 ── 视频审核 ──通过──▶ 待发布
                                    ▲                 │
                                    │                 ▼
                              进行中·发布 ──成功──▶ 发布完成
                                    │                 │
                                    └─ 失败/取消 ─┘   定时回采数据与评论
                                      （退回待发布）
```

一句话对照：

| 这一步从哪发起 | 失败/取消后退回 |
|---|---|
| 草稿 · 提交去生成提示词 | **草稿** |
| 脚本审核 · 通过去生成视频 | **脚本审核** |
| 待发布 · 去发布 | **待发布** |

非法跳步会被挡下。通用流转 `POST /task/transition` 现在**只接受「提交」**（`to=working`），
生成 / 发布 / 审核各有自己的接口——免得有人从这个口子把任务推进「进行中」却不带 `op`，
那样既没有失败退路，又会被当成「操作进行中」锁住。

**「脚本通过」= 授权生成视频**，点下去就会直接开跑（`进行中·生成视频`），所以生视频通道是在
点「通过」之前选的。生成的授权只能来自这一步——`tiktok_ops_generate` 也只在任务已经处于
`进行中·生成视频` 时才能调用，**agent 不能绕过脚本审核直接花钱**。

## 任务字段

| 字段 | 说明 |
|---|---|
| 选题 | 视频的创作方向（用户填） |
| 参考素材 | 图片 / 视频 / 网页链接 / 顾本素材 id，可多条 |
| 视频时长 | 秒 |
| 视频比例 | 竖屏 9:16 / 横屏 16:9 / 方形 1:1 |
| 生视频通道 | 顾本素材库 / MiniMax-H3（生成时还能在详情页临时切换） |
| 任务状态 | 草稿 / 进行中 / 脚本审核 / 视频审核 / 待发布 / 发布完成 |
| 生成视频的提示词 | agent 产出，脚本审核的对象 |
| 生成视频的素材 | 顾本产出的视频文件路径 |
| 任务提交时间 | 提交时写入 |
| 脚本审核时间 | 脚本通过时写入 |
| 审片时间 | 审片通过时写入 |
| 发布时间 | 发布成功时写入 |
| 反馈数据 | 观看次数 / 点赞数 / 评论数 / 分享次数 |

每条任务还有一份**流转记录**（谁在什么时候把状态推到了哪一步），在页面点「查看流转记录」展开。

## 界面在哪

**左侧导航栏只有「TikTok 运营助手」一个入口**，点进去后内容区顶部是四个页签：

| 页签 | 作用 |
|---|---|
| 运营任务 | **看板式排版**：按六个状态分列（列头带颜色点与数量），卡片上直接审核通过/驳回、生成视频、发布。**点卡片弹出任务详情**（选题/参考素材/时长/比例/提示词/素材/四个时间戳/审核意见/四项数据/流转记录）；**新建任务走右上角弹窗** |
| 视频数据 | 已发布视频的观看/点赞/评论/分享，一键采集 |
| 评论 | 采集到的评论内容 |
| 运营洞察 | 整体表现、互动率、按比例与时长的平均播放对比、播放前 5、自动化配文 |

**设置仍留在 DSH 设置弹窗**（「TikTok 运营助手」一节），里面只有 TikTok 账号 + 顾本 Token。

实现方式：`sidebar.panellist` 座位注册一个导航行、`main` 座位注册一个面板，
两者的 id 必须一致（`layout.selectPanel` 靠它切换）；四个页面只是该面板内部的页签。

## 两种素材要分清

任务上有**两个不同的素材字段**，用途完全不同：

| 字段 | 用途 | 会不会传给生成模型 |
|---|---|---|
| **参考素材** `refs` | 用户建任务时给的上下文，**给 agent 写提示词用**（网页链接、竞品图、风格参考…） | **不会** |
| **生视频素材** `genMaterials` | 真正传给生成 AI 的画面参考 | **会** |

新建任务时如果勾选「用这些参考素材直接生成视频」，参考素材才会被复制进生视频素材
（网页类会被排除——它不能当画面参考）。

### 生视频素材怎么变成顾本能用的引用

顾本 `gen --refs` 吃的是素材 id，所以：

- `guben` = 公共素材库 id → `--refs <id> --scope downloaded`
- `work` = 「我的作品」id → `--refs <id> --scope private`
- `image` / `video` = 本地绝对路径**或**图片/视频网址 → 先落盘（网址会下载），
  再 `upload-work` 换成作品 id → `--scope private`
- `url` = 普通网页 → **不能**当画面素材，只作写提示词的参考，会在「素材处理」里说明

> 顾本一次只能用一种 scope，两种都有时优先「我的作品」，被让位的那批会写进「素材处理」。
> 另外引用视频的总时长有上限（约 30 秒），超了上游会拒绝。

### 详情页可以直接预览

点开任务详情，参考素材 / 生视频素材 / 生成产物都会渲染出来：**图片直接显示、视频给播放器、
网页给可点链接**。本地文件走 `/api/tiktok-ops/file`，这个接口有白名单——**只服务出现在某个
任务素材字段里的路径**，不是任意文件读取。

## 脚本审核阶段能改什么

任务卡在「脚本审核」时，详情弹窗里除了通过/驳回，还能就地改三样东西——不用退回去重跑流程：

| 能改 | 怎么改 | 走哪个接口 |
|---|---|---|
| **提示词** | 直接在文本框里改，点「保存提示词」；或填一句优化要求，点「让 agent 优化提示词」 | `POST /task/prompt` |
| **视频时长** | 改成秒数后点「保存时长」（生成视频时按这个时长提交） | `POST /task/update` |
| **生视频素材** | 点「从顾本素材库添加…」，从选择器里挑；已加的可以「移除」 | `POST /task/materials` |

### 让 agent 优化提示词

点「让 agent 优化提示词」会**新开一个会话**（走 `session.create → session.prompt`，跟提交任务时自动派活是同一条路），
把这套上下文交给它：任务 id、选题、参考素材、目标市场、当前提示词，以及你填的优化要求。
它会先加载 `sd25-pe` skill，按官方规范重写，再用 `tiktok_ops_set_prompt` 写回**同一条任务**。

派活提示词里写死了两条约束：**只改提示词**（不要生成视频、不要改时长素材和状态），写完停下来等人工审核。
任务已经在「脚本审核」时重写是**原地更新**——`moveTask` 允许同状态自转，只记一条日志，不会跳步、不会重新提交。
跑完点右上角「刷新」看结果；被替换掉的旧版本会压进 `promptHistory`（最多留 10 版），详情里可以「回填到编辑框」。

能改提示词的状态只有「进行中」和「脚本审核」；时长与素材在「视频审核」阶段也还能改（驳回前先改好，重生成更省事）。

### 生视频素材的三个来源

选择器里三个页签，全都来自顾本素材库：

| 页签 | 来源 | 存进任务的是什么 | 生成时用的 scope |
|---|---|---|---|
| 我的作品 | 顾本「我的作品」`/works` | `{kind:'work', value:<作品id>}` | `private` |
| 公共素材（已下载） | 公共库里 `downloaded=true` 的那些 | `{kind:'guben', value:<素材id>}` | `downloaded` |
| 本地上传 | 先 `upload-work` 存进「我的作品」 | `{kind:'work', value:<作品id>, path:<本地路径>}` | `private` |

- **本地上传就是先传顾本**：选完文件立刻 POST 到 `/api/tiktok-ops/material/upload`（按流落盘，上限 300MB），
  插件调 `guben upload-work` 换成作品 id；任务里记的始终是顾本 id，同时带上本地 `path`，详情页因此能直接预览。
- 缩略图靠顾本的预签名地址（`thumbUrl` / `previewUrl`）。列表接口因此**没有走 CLI**——
  CLI 的 `works` / `search` 会把 URL 裁掉，逐个回查就是 N+1 次进程启动；列表走只读 HTTP `/api/agent/*`，
  写入类操作（上传作品、生视频）仍然只走 CLI。列表结果缓存 60 秒。
- 「已下载」在服务端没有过滤参数，是插件拉一大页到本地再筛的（公共库目前是几百条量级）。
- 顾本一次只能用一种 scope，两种混着选时优先「我的作品」，被让位的那批会写进详情里的「素材处理」。

## 提示词质量：接入了火山方舟官方 skill

生成的视频提示词不再是一句话，而是按**官方 Seedance 2.5 提示词规范**产出的结构化提示词。
做这件事的是火山方舟官方的 `sd25-pe` skill，安装命令（官方给的）：

```sh
npx --yes skills@latest add "https://arkdocs.tos-cn-beijing.volces.com/skills/" --skill sd25-pe --yes
```

> 本机 npm 缓存目录有 root 属主文件会报 EPERM，加一个独立缓存目录绕开：
> `npm_config_cache=/tmp/npm-cache npx --yes skills@latest add ...`

装好后 DSH 会自动把它纳入技能目录。插件同时会往 agent 的系统提示里注入一段使用说明
（写提示词前必须先加载 `sd25-pe`，不要凭感觉写；不要把画幅/时长/分辨率写进提示词）。

用 `/api/tiktok-ops/diag` 的 `guidance` 字段可以确认注入是否成功：

```json
{"registered": true, "reason": "ok", "mentionsSkill": true}
```

### 市场与语言默认

**默认面向欧美市场**：台词与画面文字用英语，人物、场景、道具用欧美语境，并在提示词里
明确写出「使用英语」——官方指南指出，不写明时英语台词容易被生成成中文。

任务上有 `market` 字段：`us-eu`（默认）/ `cn` / `other`。只有非默认市场才会在看板卡片上标出来。

## 模型工具

| 工具 | 作用 |
|---|---|
| `tiktok_ops_tasks` | 看任务清单（可按状态过滤）——agent 靠它找活干 |
| `tiktok_ops_create_task` | 替用户建任务 |
| `tiktok_ops_set_prompt` | 写提示词 → 推到脚本审核；任务已在脚本审核时**原地更新**（「让 agent 优化提示词」走的就是这条） |
| `tiktok_ops_set_materials` | 设置任务的「生视频素材」 |
| `tiktok_ops_guben_search` | 搜索顾本公共素材库（只读、不扣积分）——给选题找参考画面 |
| `tiktok_ops_guben_works` | 看顾本「我的作品」：列表，或传 id 看单个详情（含当初的提示词与引用素材） |
| `tiktok_ops_guben_download` | 把素材下载到本地，返回的绝对路径可直接交给 `set_materials`。⚠️ **public 素材扣积分**，work 免费 |
| `tiktok_ops_generate` | 继续一次**已被授权**的生成（仅限「进行中·生成视频」）→ 推到视频审核 |
| `tiktok_ops_publish` | 发布（仅限「待发布」） |
| `tiktok_ops_collect` | 周期巡检：采数据 + 采评论 + 重算洞察 |
| `tiktok_ops_insights` | 取运营洞察，用于推理下一轮选题 |

给 agent 的素材链路是连起来的：**`guben_search` 找 → `guben_download` 落到本地 → `set_materials`（kind 用 image/video、value 填本地路径）→ 脚本审核通过就生成**。

界面侧另有三条 agent 用不到的接口：`/guben/works`、`/guben/materials`（素材选择器的列表）、`/material/upload`（本地上传）。

## 提交任务会自动派活给 agent

**提交任务时会自动创建一个 agent 会话**，把选题、参考素材、市场、时长比例投给它，
并明确要求「先加载 sd25-pe skill，按官方规范写提示词，推到脚本审核后停下等人工审核」。

实现走的是任务看板同一套 RPC：`session.create → session.rename → session.prompt`
（typert gateway）。`/api/tiktok-ops/diag` 的 `dispatch` 字段能确认网关是否可用：

```json
{"gateway": true, "workspaces": true}
```

派活失败**不会**让创建任务失败——原因会写进任务的流转记录，卡片上也会出现
「让 agent 处理」按钮可以手动重试。想只建任务不派活，请求里带 `dispatch: false`。

> 每提交一条任务就会起一个会话，**会消耗 API 额度**。存草稿不会派活。

## 「进行中·生成提示词」是在等 agent

**插件没有后台 worker。** 任务提交后会进入「进行中·生成提示词」，等 agent 来读任务、写提示词。
这不是 bug，是设计——但需要一个触发源。四种方式：

1. **对话里直接说**：「处理一下 TikTok 运营助手的任务队列」，agent 会调 `tiktok_ops_tasks` 找活干。
2. **任务看板定时**（推荐，见下）。
3. **页面上手动**：草稿可「提交」、卡片上可「让 agent 处理」、脚本审核可「通过并生成视频」、待发布可「发布」。
4. **卡住了就取消**：这一步也属于「进行中」，所以同样不能改不能删；等不来 agent 就点「取消当前操作」，
   任务退回草稿，改完再重新提交。

⚠️ 插件如果在某个会话开始**之后**才装好，那个会话不会自动获得 `tiktok_ops_*` 工具
（工具清单在会话建立时投影）。**新开一个对话即可。**

## 自动化：在任务看板建两条重复任务

DSH 任务看板的 cron 没有对外暴露成服务，它的定时是驱动自己的任务去唤起 agent 会话。
所以接法是：**建重复任务，提示词让 agent 去调本插件的工具。**

| 用途 | 建议 cron | 提示词 |
|---|---|---|
| ① 处理任务队列（让「进行中」动起来） | `0 */2 * * *` | `处理 TikTok 运营助手的任务队列：用 tiktok_ops_tasks 找出「进行中」的任务，针对每条任务的选题和参考素材，用 tiktok_ops_set_prompt 写出生成视频的提示词，推到脚本审核。` |
| ② 数据巡检（回采数据与评论） | `0 */6 * * *` | `执行 TikTok 运营助手的数据巡检：调用 tiktok_ops_collect 采集观看/点赞/评论/分享与评论内容，再用 tiktok_ops_insights 看运营洞察，并给出下一轮选题建议。` |

这两段也写在页面「任务」和「洞察」页签里，不用回来翻文档。

## 安装

### 方式一：团队成员从私有 GitHub 仓库装（推荐）

**前提**（每人各自准备一次）：Node ≥ 22.19、`pnpm`、`dsh`，并让 git 能访问私有仓库
（配好 SSH key，或 credential helper）。

```sh
# SSH（私有仓库推荐）。<sha> 换成仓库里的具体提交，便于复现
dsh plugin --profile web add git+ssh://git@github.com/<组织>/<仓库名>.git#<sha>

# 或者 github: 简写（同样要求 git 已能认证）
dsh plugin --profile web add github:<组织>/<仓库名>#<sha>
```

装完**重启一次 dsh**——新加入的 bundle 不会应用到正在运行的进程：

```sh
dsh --profile web        # 或 dsh web
```

验证真的装上了（别跳过：`add` 成功只代表 pnpm 解析成功，不代表 profile 会加载它）：

```sh
dsh plugin --profile web list --depth 0
# dsh-tiktok-ops 应当出现，并带一个已解析的版本
```

**每位成员各自要做的**（这些是**本机状态**，不在仓库里，互不影响）：

1. GUI →「设置 → TikTok 运营助手」
2. 填 **TikTok 账号**（各自的号）、**顾本素材库 API Token**、**MiniMax H3 API Token**（可选）
3. 点「登录」完成一次 TikTok 登录

**不需要**另外安装 `guben-material` —— 顾本 CLI 已内联在 `vendor/guben.mjs`。

> 队友想用自己那份更新的 CLI，设置页有「CLI 路径」一栏可覆盖，留空就用内联副本。

### 方式二：本机目录直接安装（开发用）

```sh
sh scripts/install.sh web          # 软链进 profile + 写补丁行
sh scripts/install.sh web --uninstall
```

装完同样**需要重启一次 dsh web**（profile 的 patch 监听只重读补丁文件，不会重新 import
已缓存的 ESM 模块）。也**不要**用 kill 重启：`dsh-doctor` 监督器对正常退出不会自动拉起，
非零退出还会记 incident，连续 2 次直接 quarantine。

重启后验证：

```sh
npm run verify
```

## 生视频：两条通道，生成时选

任务详情页的「生成视频」旁边有一个**通道下拉**，二选一：

| 通道 | 吃什么 | 计费 | 说明 |
|---|---|---|---|
| **顾本素材库**（默认） | 素材 **id** | 顾本积分 | 老路子。素材经 `--refs <id> --scope private/downloaded` 传给模型 |
| **MiniMax-H3** | 提示词 + 参考素材**字节** | MiniMax 账号按量 | 直连 MiniMax「视频生成 V2」，最高 2K |

选择会记到任务上（`provider`），下次默认沿用；agent 调 `tiktok_ops_generate` 时也能用 `provider` 参数覆盖。

### MiniMax-H3 对接细节

对接的是 [视频生成 V2](https://platform.minimax.cn/docs/api-reference/video-generation-v2-create)：

```
POST /v2/video_generation                    → { task_id }
GET  /v2/query/video_generation/{task_id}    → succeeded 后 content.url 是限时下载地址
```

驱动在 `lib/minimax.js`，只做「建任务 → 轮询 → 把产物拉到本地」；素材怎么取字节由 `impl.js`
负责（只有它知道顾本作品怎么下载），这样驱动可以注入假 `fetch` 做离线测试。

**参考素材怎么传**：顾本要素材 id，MiniMax 要「能取到的字节或公网地址」，所以两条路的素材语义不同：

- 公网 URL → 直接透传给 MiniMax（省一次 base64）
- 本地文件 → `data:image/<格式>;base64,...`
- 顾本作品/素材 → 先 `download-work` / `download` 拉到本地，再转 data URI

参考素材统一用 **`reference_image` / `reference_video`** 角色，**不用 `first_frame`**：
文档明确「图生视频与多模态参考生视频互斥」，而且一旦用了首帧，宽高比就被图片锁死成 `adaptive`，
就没办法按任务的竖屏/横屏出片了。

**档位自动夹取**（提交前就夹，不等上游报 400）：

| 模型 | 分辨率 | 时长 |
|---|---|---|
| `MiniMax-H3` | 768P / 2K | 4~15 秒 |
| `MiniMax-H3-Max` | 480P / 768P（不支持 2K） | 5~15 秒 |

任务时长不在区间内会被夹到边界并写进「素材处理」说明。

**体积限制**：接口要求请求体 ≤ 64MB，base64 放大约 33%，所以单个素材超过 30MB 会**跳过**并在
「素材处理」里说明，而不是等上游返回一个看不懂的 400。

### 平台域名：国内 / 国际的 Key 不通用

MiniMax 有国内（`api.minimax.cn`）与国际（`api.minimax.io`）两套平台，**API Key 不能混用**。
填错区的典型症状是「Token 保存成功，但一调用就 401 / 1004」。所以设置页里把域名做成了显式选项，
并提供 **「测试连接」** 按钮：它走只读的查询接口（查一个不存在的 `task_id`），
**不建任务、不花钱**——鉴权不过回 401/403，鉴权通过则回 400 之类的「task_id 无效」，
据此判定 Key 到底能不能用，比盯着「已配置」三个字可靠。

### 轮询要扛得住网络抖动

任务一旦建成功，**钱就已经花了**，所以轮询与下载都带重试：网络层错误（没有 HTTP 状态码）、
`429`、`5xx` 会退避重试（默认 4 次，2s 起指数退避），`4xx` 业务性失败直接抛。

这不是过度设计——实测踩过：一个 15s/768P 的任务在上游正常跑，本地轮询到第 224 秒时一次
`fetch failed`，旧代码就把整单判成失败。任务其实还在跑，最后是手工把产物捞回来的。
真要放弃也得是「确认失败」，不能是「一次网络抖动」。

### 成片听不到声音？先别怀疑模型

MiniMax H3 生成的是**带音轨**的视频（`t2va` = text→video **+ audio**），容器里是 AAC 立体声，
正常码率 ~130 kbps。曾经踩过一次坑：详情页播放器**写死了 `muted: true`**，
于是有声的成片放出来也是静音，看上去就像「模型没生成声音」。
现在播放器默认不静音，成片还换成了更大的播放器（竖屏 9:16 若按缩略图限高 160px，宽度只剩 90px，根本没法审片）。

真要判断一个 mp4 有没有声音、是不是静音，看两点就够：

- 有没有 `soun` 轨：`moov/trak/mdia/hdlr` 的 handler 是 `soun`，编码 `mp4a`；
- AAC 帧大小分布：**纯静音会压得极小**（几乎全是几十字节的小帧），
  有内容的轨中位帧在 500B 上下。15 秒 473 帧、中位 512B ⇒ 确实有声音。

### 生成失败会退回脚本审核，不会假装成功

脚本审核「通过」触发的生成和 `tiktok_ops_generate` 走同一个 `startVideoGeneration()`，守卫只有一份：

**两种情况都算失败——上游抛异常（凭据错、网络不通）、或正常返回但 `files` 为空。
两种都会把真实原因写进流转记录，并 `failOp` 退回脚本审核。**

这条以前是缺的，而且缺了两层：

1. 顾本那条路在任务失败时**仍然是正常退出（退出码 0）**，失败信息只在 JSON 的 `task.error` 里，
   而旧代码不看 `files` 就推进到「视频审核」，于是「没生成出来」被记成「视频已生成，等待审片」，
   人工在审片页看到空白。MiniMax 那条同理（错误是 `{ code, message }` 对象，
   `generationFailureReason()` 会把两家的错误都归一成一句话）。
2. 抛异常那条路（比如 401）以前连流转记录都不写，页面上只闪一个 toast，事后**完全看不出为什么没生成**。

## 配置

落地页「设置」填三样：

- **TikTok 账号**：用户名/邮箱 + 密码
- **顾本素材库 API Token**：素材网「个人中心 → Agent 接入」生成
- **MiniMax H3 API Token**：MiniMax 开放平台「账户管理 → 接口密钥」生成，
  另可选模型（`MiniMax-H3` / `MiniMax-H3-Max`）与分辨率

两个 Token 都只进不出：`/state` 里一律回 `***`，把 `***` 或空串写回去不会覆盖已存的真 Token。

素材网地址与 agent-browser 路径自动探测。顾本凭据写在
`$DSH_HOME/tiktok-ops/guben-home/.guben/config.json`（0600），
**不会覆盖**你 `~/.guben/config.json` 里已有的 token。

### 顾本 CLI 是内联的，不用另外装 guben-material

插件自带一份顾本 CLI（`vendor/guben.mjs`，21 KB，零 npm 依赖），所以**开箱可用**。

早先它只去插件同级目录找 `../guben-material/scripts/guben.mjs`：开发机上同级目录存在所以能跑，
但用户从 npm 装进 `node_modules/` 之后同级什么都没有，而路径又不能在设置里填——
结果顾本通道对新用户完全是死的。现在解析顺序是：

```
用户显式配置  >  vendor/guben.mjs（内联）  >  同级目录老布局
```

设置页有「CLI 路径」一栏可以覆盖（想用自己那份更新的 CLI），留空就用内联副本，
旁边的「恢复内联副本」一键清掉覆盖。存的路径会在保存那一刻校验（必须存在、是绝对路径、`.mjs`/`.js`），
而不是等生成时才报「脚本不存在」。

> `vendor/README.md` 记着内联副本的 sha256 与同步方法。**更新那份副本时只拷 `guben.mjs`，别用 `cp -r`**
> ——`guben-material/scripts/config.json` 里存着真实 Token。测试里有一条断言专门盯着这个。

## 数据与安全

- 数据文件：`$DSH_HOME/tiktok-ops/state.json`（0600）
- **TikTok 账号密码明文存储**（按需求实现）。仅限本机自用；把 `dsh web` 暴露到外网时不要配置账号。
- 自动登录遇到验证码/二次验证会转成 `need_manual`，在自动打开的窗口里手动登录一次即可。
- **登录有强制冷却**：失败后退避 30 分钟 → 2 小时 → 8 小时（封顶）。冷却期内「登录」按钮不可点，
  想提前重试要显式点「我已确认可重试」。这是为了防止频繁自动化登录把账号刷到被 TikTok 锁定。
- 数据指标里的 `shares` 若长期为 0，通常是创作中心没开「分享」列，不是没人分享。

## 已知限制

- **未登录时会明确拒绝并告诉你去登录**。发布、采集数据、采集评论都先检查登录态——
  否则未登录时上传页会重定向或空白，只会抛一句「Element not found」，看不出真实原因。
  上传页渲染慢时也会先在页面内等文件选择框（最多 60 秒）再操作。
- **数据与评论是 DOM 采集**，创作中心改版就会失效。失败时自动留现场截图到
  `$DSH_HOME/tiktok-ops/diagnostics/`，路径写进错误信息与页面。
- **「分享次数」在创作中心默认不显示**。内容页要手动开启分享列，否则该项恒为 0——
  洞察里会显式提示 `sharesAvailable=false`，避免把「没数据」误读成「没人分享」。
- 发布走网页上传，不是官方 API。需要稳定请改用官方 Content Posting API（要过应用审核）。
- **「下一条拍什么」不在插件里自动下结论**：插件只做确定性统计，推理交给 agent
  （它能看到完整的选题与提示词上下文）。
- **MiniMax 那条路不支持首尾帧**。参考素材统一按 `reference_image` / `reference_video` 传，
  因为文档规定「图生视频与多模态参考生视频互斥」，而且用首帧会把宽高比锁成 `adaptive`，
  没法按任务的竖屏/横屏出片。要做首尾帧得再开一个通道。
- **MiniMax 的参考素材走 base64 内联**，单素材超过 30MB 会被跳过（接口请求体上限 64MB）。
  真要用大视频当参考，得先把素材放到公网 URL 上，或改用文件上传接口换 `mm_file://`。

## 开发与测试

```sh
npm run verify           # 安装 + 运行时一键验证（14 项）
npm test                 # 离线：宿主 241 项 + 客户端 98 项
npm run test:host        # 只跑宿主：路由 + 六态流转 + 审核 + 提示词改写 + 素材选择器 + 洞察 + MiniMax 驱动
npm run test:client      # 只跑客户端：自带最小 React，把 client.js 真渲染一遍并断言发出的请求
npm run test:parser      # 创作中心列表解析，含分享列（33 项，fixtures 是真实抓取的页面文本）
npm run test:drivers     # 联调：真实顾本 API（只读）
npm run test:diagnostics # 失败留证：未登录会话下会截图并带路径
npm run uninstall:plugin
```

`test:client` 不装 React、不开浏览器：手写一个最小 React（`createElement` / `useState` / `useEffect` /
`useSyncExternalStore`）把组件函数跑一遍，再断言渲染内容与交互时打出去的请求体。
**客户端半只有重启 dsh web 才会加载**，改坏了要到用户那里才发现，所以这层冒烟测试是必要的。

**发布与评论回复没有自动化测试**——会产生对外副作用，需要人工触发。

## 改动怎么生效

| 改了什么 | 生效方式 |
|---|---|
| `lib/impl.js`（宿主：路由/工具/流转） | 重新挂载插件行即可（`lib/index.js` 用带时间戳的动态 import 绕开 ESM 缓存） |
| `lib/client.js`（界面） | 客户端 bundle 由 `dsh-client-modules` 重新组合，**需要重启 dsh web**，或让 profile 的 patch 层重新挂载 |
| `package.json` / 依赖 | 必须重启 dsh web |

本机实测：直接改 `~/.dsh/profiles/web/cordis.patch.yml`（追一行注释）**不一定会触发重挂载**——
patch 内容没变时 `entry.update` 是空操作。稳妥做法还是在启动 dsh web 的终端里 Ctrl+C 后重启
（不要用 kill：`dsh-doctor` 对正常退出不会自动拉起）。
